### C0002-INT-01 — B001 is a bundled treatment, not a fresh-boundary implementation

- **Internal item or claim ID:** `C0002-INT-01`; based on the accepted branch-design record derived from `C0001-INT-01` through `C0001-INT-07`.
- **Status:** Accepted branch-design fact.
- **Exact file:** `AGENT_PROTOCOL.md`; accepted restatement in `branches/B001/state/current_state.md`, Accepted Factual Record.

### C0002-INT-02 — Same-model agreement is not independent evidence

- **Internal item or claim ID:** `C0001-INT-05` as accepted in the branch factual record.
- **Status:** Accepted protocol and branch-design fact.
- **Exact file:** `AGENT_PROTOCOL.md`; `branches/B001/state/current_state.md`, Accepted Factual Record and Known Objections and Contradictions.

- **Limitations:** This is a rule against an invalid inference, not evidence about the magnitude or direction of a fresh-versus-persistent effect.

### C0002-INT-06 — Conditional architecture fit is the accepted interpretation

- **Internal item or claim ID:** `C0001-INTG-01`.

### C0002-INT-07 — Full compute isolation remains unresolved

- **Internal item or claim ID:** `C0001-INTG-02`.
- **Status:** Accepted evidence-gap conclusion.
- **Exact file:** `branches/B001/state/current_state.md`, Current Claims; `branches/B001/summaries/C0001_dense.md`, Main and Alternative Interpretations and Unresolved Questions.
- **Relevance:** Prompt processing, context processing, completion, final answer, orchestration, state construction, handoff generation, tools, samples, and selection can differ even when a nominal reasoning-token cap is equal. Package construction and longer retained context are therefore treatments with costs, not free controls. A state or access comparison cannot receive a causal interpretation until a primary compute-matching rule and freed-budget rule are declared.
- **Limitations:** This establishes a missing control, not the correct primary compute measure. The branch has not selected the matching resource, tolerance, or reallocation policy.

## Relevant Hypotheses and Speculation

- **`C0001-EXP-01` — Independent fresh-role effect:** Unresolved and weakened. The branch retains only the possibility of a conditional effect after full controls; it has no internal empirical support for direction or magnitude.
- **`C0001-EXP-02` — External memory and provenance:** Qualified. Structured state may matter, but workflow memory cannot be generalized to provenance correctness, and state must be treated as an active intervention.
- **`C0001-EXP-04` — Context-partition benefit:** Narrow hypothesis. Partitioning may help under severe corruption, but fresh invocation is not isolated.
- **Fresh-context-plus-state interaction:** Hypothesis in `current_state.md`. Fresh execution may reduce contamination only when external state preserves required dependencies. No accepted threshold, metric, or causal estimate exists.
- **`C0002-EXP-01` — Boundary-only null:** Plausible but presently non-identifiable unless a residual package-matched persistent-versus-fresh manipulation is defined and verified.
- **`C0002-EXP-02` — Contamination-reduction benefit:** Hypothesis. It requires lineage evidence of less preservation or amplification without lower coverage or task completion.
- **`C0002-EXP-03` — Interface-loss harm:** Hypothesis consistent with the qualified C0001 interface-loss risk, but still not isolated from package representation and retention.
- **`C0002-EXP-04` — State-completeness threshold:** Not operational as written. The Critic shows that schema compliance, retention, dependency coverage, package size, and transformation type must be separated.
- **`C0002-EXP-05` — Structured-state dominance:** Hypothesis compatible with the C0001 alternative that functional scaffolding, state, memory, and verifier information explain useful effects.
- **`C0002-EXP-06` — Hidden-context privilege:** Mainly a design diagnosis. More authorized prior trace is an observable access difference, not evidence of a metaphysical boundary effect.
- **`C0002-EXP-07` — Compression-as-treatment:** Hypothesis with no direct branch evidence. It should be represented by measurable deletion, summarization, token, or transformation rules and charged costs.
- **`C0002-EXP-08` — Stage-specific sensitivity:** Explicit speculation. No accepted branch evidence identifies a sensitive transition.

Repeated appearance of these ideas is not independent support. The branch contains one accepted C0001 state plus current C0002 proposals and criticism, not multiple independent confirmations.

## Prior Contradictions or Objections

1. **Context protection versus interface loss:** `C0001-SRC-01` supports a narrow benefit under severe context corruption, while `C0001-SRC-02`, `C0001-SRC-07`, and `C0001-EXP-05` support risks from sequential dependency loss, withholding, and propagation. This contradiction motivates an interaction design; it does not establish a threshold.
2. **Structured state versus freshness:** `C0001-SRC-12` supports active external records in a navigation setting, while no stored study isolates fresh context after state and costs are matched. Any apparent fresh effect could be a state-information effect.
3. **Full-trace persistent versus fresh:** The Critic objects that this contrast changes information quantity, retrieval opportunity, context length, salience, and cost. It estimates prior-trace privilege plus associated effects, not a boundary alone.
4. **Package-only persistent versus package-only fresh:** The Critic objects that, once prior trace is inaccessible and visible packages are equal, the branch has not identified what functionally relevant property remains different. A null could indicate treatment collapse rather than a true zero effect.
5. **Scalar completeness versus task-relative retention:** A package can fill every schema field and omit a critical relation, or be concise while preserving all predeclared dependencies. Defining completeness from success is circular and allows post hoc thresholds.
6. **Lower unsupported claims versus lower coverage:** Accepted measurement requirements reject interpreting fewer unsupported claims without claim count, factual coverage, citation completeness, task completion, and usefulness.
7. **Recorded cost versus matched compute:** A full ledger is necessary but insufficient. The branch still needs a primary resource rule and a declared treatment of saved or excess budget.
8. **Semantic similarity versus epistemic preservation:** A claim may remain textually similar while its status, qualification, support, or contradiction relation changes. Similarity alone cannot establish retention.
9. **Null outcomes versus hypothesis discrimination:** Similar results can support a true boundary null, state dominance, treatment collapse, task insensitivity, or inadequate manipulation. Manipulation checks are mandatory.
10. **Observable trace versus inaccessible reasoning:** Repository inspection can audit messages, files, fields, and permissions. It cannot establish what occurred in inaccessible internal reasoning and should not use that quantity in an estimand.

## Changes Across Recent Cycles

Only C0001 is available as a preceding dense summary.

- **From broad architecture comparison to factor identification:** C0001 rejected general multi-agent superiority and the original four-condition ladder as a clean causal design. C0002 narrows the frontier to trace access and state transfer.
- **From “fresh-boundary isolation” to an observable access decomposition:** The C0001 summary suggested matched persistent versus fresh execution. C0002’s Critic corrects this by requiring full-trace persistent, package-only persistent, and package-only fresh conditions, with the last contrast treated as a boundary test only if a residual manipulation exists.
- **From scalar state completeness to multiple measured dimensions:** C0001 left informational equivalence and state completeness unresolved. C0002 separates schema compliance, predeclared retention, task-relative dependency coverage, package size, and transformation type.
- **From outcome metrics to manipulation checks plus outcome metrics:** C0001 accepted claim-level, coverage-sensitive lineage evaluation. C0002 adds checks for supplied inputs, accessible trace, package contents, field compliance, dependency retention, context length, stage costs, claim count, and coverage.
- **From a favored contamination-control story to explicit disconfirmation:** C0002 requires evidence where reset loses valid qualifications, gains vanish under coverage controls, full-trace access explains the effect, or state representation dominates.
- **No new accepted empirical evidence has entered the branch in C0002 yet.** The Explorer and Critic files are current-cycle proposals and objections, not accepted state.

## Questions Requiring External Evidence

1. Are there primary controlled studies comparing full prior-trace access with standardized-package-only access while holding model, task, stage instructions, visible evidence, tools, sampling, selector, evaluator, and compute approximately constant?
2. Are there primary reset or fresh-context studies that state exactly what remains different after prior-message visibility and serialized inputs are equalized?
3. Are there methods that independently manipulate state serialization, retention, summary fidelity, claim-ledger structure, or handoff compression rather than bundling them with agent count or prompts?
4. Are there validated methods using a predeclared information inventory or dependency reference to score preservation, omission, contradiction, status change, mutation, correction, and amplification?
5. Are there evaluator designs with reported reliability for those lineage categories?
6. Are there studies showing reset or package-only access losing valid qualifications or dependencies, especially on sequential tasks?
7. Are there studies where apparent lower factual-error rates disappear after controlling claim count, answer length, factual coverage, citation completeness, or task completion?
8. Are there studies that fully account for prompt and context processing, package construction, completion, tools, candidates, selection, orchestration, and final-answer cost, and that declare how saved budget is handled?
9. Are there studies comparing structured state with unstructured prior trace under matched information inventory and cost?
10. Is there direct evidence on open-ended multi-source research synthesis rather than only short-answer reasoning, static QA, navigation, or synthetic handoff tasks?

For every source, the External Evidence Researcher should extract an intervention matrix: model, task, prompts, role labels, stage instructions, prior-trace access, visible inputs, state artifact, retention or compression rule, evidence, tools, candidate count, selector, evaluator, context length, generation cost, final-answer cost, coverage measures, and manipulation checks.

## Handoff to External Evidence Researcher

Use the corrected observable contrast structure below. Do not treat all contrasts as evidence about freshness.

| Contrast | Observable difference | Permissible interpretation | Required checks |
|---|---|---|---|
| Full-trace persistent vs package-only persistent | Authorized access to prior trace, plus associated context length and cost | Prior-trace access effect | Verify trace accessibility, package identity, context length, stage costs, coverage, and claim count. |
| Package-only persistent vs package-only fresh | Conversation/container continuity after visible inputs and trace access are matched | Boundary contrast only if a distinct residual property is defined and verified; otherwise equivalence or implementation-control comparison | Name the residual manipulation; match role prompts, permissions, tools, model settings, and inputs; verify no prior trace access. |
| Same continuity, structured package vs unstructured or weak package | State representation and field structure | State-representation effect | Predeclare fields; check field compliance and package content. |
| Same continuity and format, higher vs lower predeclared retention | Proportion of a reference inventory retained | Retention effect | Predeclare inventory and dependencies before scoring; measure omissions and status changes. |
| Same information target, concise vs expanded or transformed package | Compression, transformation, and package cost | Compression/transformation effect | Record deletion, summarization, normalization, tokens, context cost, and dependency preservation. |
| Any condition with different candidate or selector opportunities | Sampling or selection allocation | Sampling/selection effect, not state or boundary effect | Match or explicitly model candidate count, selector access, and cost. |

Classify each external source as one of: direct evidence on the corrected trace-access or verified residual-boundary estimand; indirect evidence on state or handoff design; measurement method only; or non-discriminating because interventions remain bundled.

The most important unresolved external target is whether any study identifies a noncollapsed package-only persistent-versus-package-only fresh manipulation. If none does, say so directly. Separately seek evidence against contamination reduction: reset-induced loss of valid dependencies, fresh gains erased by coverage controls, full-trace effects explaining apparent gains, or state-format effects dominating boundary comparisons.
